# 免费个人博客搭建指南

GitHub Pages + Jekyll Chirpy 主题 | 一份零基础、零代码、零成本的个人博客搭建完整指南 | 基于真实学习历程整理 | 全程约 30 分钟 | 永久免费

---

## 一、准备工作

### 1. 明确博客用途与定位

在开始搭建之前，先想清楚这个博客是用来做什么的。是记录个人生活随笔，还是分享读书笔记，还是记录工作经验，或者综合用途都有？想清楚这一点，有助于你后续给博客起一个合适的名字，以及决定用什么分类和标签来组织文章。

博客名称和一句话简介也要提前想好。名称最好简短有记忆点，简介最好能概括你的博客气质。比如"在野哇"配上"观物察己，感时应物。"就很有个人风格。

### 2. 准备必要材料

开始搭建之前，你需要准备以下几样东西：

第一，一个可以正常收发邮件的邮箱，用来注册 GitHub 账号。QQ 邮箱、Gmail、163 邮箱都可以。

第二，一张头像图片。可以是你的个人照片，也可以是你喜欢的插画或图标。建议是正方形图片，尺寸至少 200×200 像素，格式为 JPG 或 PNG。

第三，想好博客的名称和一句话简介。

第四，一台电脑。虽然手机也勉强可以操作，但强烈建议用电脑，操作更稳定方便。

### 3. 了解整体流程与预计时间

整个搭建过程分为七个步骤，预计总时间约 30～40 分钟：

注册 GitHub 账号，约 5 分钟；从模板创建仓库，约 3 分钟；开启 GitHub Pages 部署，约 3 分钟；修改博客基本信息，约 10 分钟；上传头像和完善 About 页面，约 10 分钟；发布第一篇文章，约 5 分钟；验证上线效果，约 3 分钟。

## 二、工具选择

### 1. 为什么选 GitHub Pages + Jekyll

搭建个人博客的方式有很多，比如 WordPress、Typecho、Hugo、Hexo、Notion 建站等等。但对于零基础的普通人来说，GitHub Pages + Jekyll 是目前最推荐的免费方案，理由如下：

完全免费，永久有效，不需要购买服务器，也不需要购买域名；无需安装任何软件，全程在网页上操作；无需写一行代码，点点鼠标就能完成；拥有独立的专属网址，格式为"你的用户名.github.io"；内容存储在 GitHub，安全可靠，不会丢失；支持分类、标签、搜索、评论、夜间模式等常用功能。

### 2. 为什么选 Chirpy 主题

Jekyll 有很多主题可以选择，我们推荐 Chirpy 主题，原因是：界面简洁大方，中文显示效果好；功能齐全，开箱即用，不需要额外配置；有专门的 Starter 模板，新手直接用即可；社区活跃，遇到问题容易找到解决方案。

### 3. 两种部署方式对比

GitHub Pages 有两种发布方式，理解它们的区别非常重要。

第一种是"Deploy from a branch"（从分支部署）。这种方式会直接把你上传的文件原封不动地发布出去。适合纯 HTML 网站，但对于 Jekyll 博客来说，用这种方式会发布源代码而不是真正的网页，打开博客会看到乱码或空白。

第二种是"GitHub Actions"（自动构建后发布）。这种方式会先把你的文件自动"编译处理"一遍，把 Jekyll 模板转换成真正的网页，再发布出去。Chirpy 主题必须使用这种方式。

打个比方：第一种方式是把食材直接端上桌，第二种方式是先自动把食材做熟再端上桌。我们要选第二种。

### 4. GitHub Pages 容量与限制说明

GitHub Pages 对个人用户完全免费，容量限制如下：仓库建议不超过 1GB，软上限为 5GB；单个文件不超过 100MB；每月流量限制为 100GB，对个人博客完全够用。

一张博客封面图压缩后约 200～500KB，1GB 空间可以存储 2000～5000 张图片。按每周发一篇文章、每篇一张封面图计算，约需 19 年才能用完，完全不用担心容量问题。

## 三、分步搭建

### 第一步：注册 GitHub 账号

GitHub 是全球最大的代码托管平台，我们的博客文件将存放在这里。

打开浏览器，访问 https://github.com，点击右上角的"Sign up"按钮。

填写注册信息：在"Email address"栏填入你的邮箱；在"Password"栏设置一个密码，要求 8 位以上，包含字母和数字；在"Username"栏填入你的用户名。

用户名的选择非常重要，因为它会直接成为你博客网址的一部分。例如你填"zhangsan"，你的博客地址就是"zhangsan.github.io"。用户名建议使用拼音或英文，简短好记，避免特殊符号。用户名一旦确定很难更改，请认真选择。

完成人机验证后点击"Create account"，然后去邮箱查收验证邮件，点击邮件里的验证链接，完成注册。

### 第二步：从 Chirpy 模板创建仓库

仓库就是存放博客所有文件的地方，我们使用现成的 Chirpy Starter 模板，一键生成完整的博客结构。

在浏览器访问 https://github.com/cotes2020/chirpy-starter，点击页面右上角的绿色按钮"Use this template"，在下拉菜单中点击"Create a new repository"。

进入创建页面后，在"Repository name"输入框中填入你的仓库名称。这个名称必须严格按照"用户名.github.io"的格式填写，例如用户名是"zhangsan"，就填"zhangsan.github.io"，一个字母都不能错。

可见性选择"Public"（公开），然后点击绿色按钮"Create repository"，等待几秒钟，仓库就创建成功了。

关于仓库名称有一点需要说明：每个 GitHub 账号只能有一个主站，仓库名必须是"用户名.github.io"，访问地址最干净。如果以后想再建第二个博客，仓库名可以随便取，比如"notes"或"teaching"，访问地址就是"用户名.github.io/notes"，可以建无限个。

### 第三步：开启 GitHub Pages 部署

创建仓库后，需要告诉 GitHub 把这个仓库发布成网站。

在仓库页面点击顶部菜单栏最右边的"Settings"（设置），在左侧边栏向下找到"Pages"，点击进入。在"Build and deployment"部分，找到"Source"下拉菜单，选择"GitHub Actions"，不要选"Deploy from a branch"。选完后页面会自动保存。

等待约 1～3 分钟后，页面顶部会出现绿色提示"Your site is live at https://用户名.github.io/"，说明博客已经成功上线了。

### 第四步：修改 _config.yml 基本信息

博客的基本信息，包括名称、简介、网址、时区等，都存放在仓库根目录的"_config.yml"文件里。

在仓库文件列表中点击"_config.yml"文件名，进入后点击右上角的铅笔图标（Edit this file）进入编辑模式。

需要修改以下几个关键字段：

找到"title: Chirpy"，改成你的博客名称，例如"title: 在野哇"；找到"tagline: A text-focused Jekyll theme"，改成你的一句话简介，例如"tagline: 观物察己，感时应物。"；找到"url: """，填入你的博客地址，例如"url: 'https://用户名.github.io'"；找到"timezone:"，改成"timezone: Asia/Shanghai"设置为中国时区；找到"name: your_full_name"，改成你的名字；找到"email:"，可以填入你的邮箱，不想公开可以留空。

修改完成后，拉到页面底部点击"Commit changes"按钮，弹出确认框后再次点击"Commit changes"保存。

注意事项：修改 _config.yml 时格式很重要，冒号后面必须有一个空格；中文内容不需要加引号；英文网址需要加英文双引号。

### 第五步：上传头像

提前把头像图片重命名为简单的英文文件名，例如"avatar.jpg"，避免重复后缀，确保文件名是"avatar.jpg"而不是"avatar.jpg.jpg"。

在仓库页面进入"assets"文件夹，点击右上角"Add file"，选择"Upload files"，将头像图片拖入上传区域或点击选择文件，上传完成后点击"Commit changes"保存。

接下来在"_config.yml"文件中找到"avatar:"这一行，改成"avatar: /assets/avatar.jpg"（文件名要和你上传的一致），保存后等待 1～2 分钟，刷新博客，左上角的空白圆圈就会变成你的头像。

### 第六步：完善 About 页面

About 页面是读者了解你的地方，值得认真填写。

进入仓库"_tabs"文件夹，点击"about.md"文件，点击铅笔图标进入编辑模式。

文件里的前五行是头信息，控制页面的基本属性，保留不动。从第六行开始，删除默认的提示文字，用 Markdown 格式写入你的自我介绍内容。可以包括你是谁、你在做什么、这个博客主要写什么、如何联系你等内容。

写完后点击"Commit changes"保存，等待 1～2 分钟刷新博客，点击侧边栏"关于"就可以看到效果。

## 四、发布上线

### 第一步：发布第一篇文章

所有文章都存放在仓库的"_posts"文件夹里，文件名格式必须严格遵守，格式为"年份-月份-日期-文章英文标题.md"，例如"2026-05-03-hello-world.md"。注意日期和标题之间用短横线连接，标题用英文或拼音，不能用中文。文章标题是在文件内部设置的，文件名只是用于排序。

每篇文章的最顶部必须有头部信息（称为 Front Matter），格式如下：

三个短横线开始，title 填文章标题（可以用中文），date 填发布日期和时间，格式为"2026-05-03 10:00:00 +0800"，+0800 代表中国时区，categories 填文章分类，用方括号，可以填大分类和小分类，例如"[随笔, 生活]"，tags 填标签，用方括号，可以填多个，例如"[第一篇, 读书]"，description 填文章摘要，会显示在首页列表里，最后三个短横线结束。

头部信息结束后，换行开始写文章正文内容。

操作步骤：进入"_posts"文件夹，点击"Add file"选择"Create new file"，在顶部输入框填写文件名，在编辑区域粘贴头部信息和正文，点击"Commit changes"保存。

### 第二步：Markdown 写作语法速查

Markdown 是博客写作使用的排版语言，用简单的符号代替格式操作，非常容易上手。

标题：在文字前加"#"号，一个"#"是一级标题，两个"##"是二级标题，三个"###"是三级标题。

正文格式：用两个星号包裹文字实现加粗，例如"**加粗文字**"；用一个星号包裹实现斜体，例如"*斜体文字*"；用两个波浪号包裹实现删除线，例如"~~删除线~~"。

列表：无序列表在每行开头加"- "（短横线加空格）；有序列表在每行开头加"1. "（数字加点加空格）。

插入链接：格式为 `[链接文字](网址)`，例如 [点击访问](https://github.com)。

插入图片：格式为 `![图片描述](图片网址)`。

引用：在段落开头加"> "（大于号加空格），文字会显示为引用样式。

分隔线：单独一行输入三个短横线"---"，会显示为一条分割线。

Markdown 的精髓是专注写作内容，不用操心排版，保存后博客会自动把这些符号渲染成漂亮的格式。

### 第三步：给文章添加封面图

封面图会显示在首页文章列表和文章顶部，让博客看起来更丰富生动。

在文章头部信息里加入以下内容：image 字段下填 path 和 alt 两个子字段，path 填图片的网址或仓库路径，alt 填图片的描述文字。

找免费高质量图片推荐两个网站：https://unsplash.com 和 https://www.pexels.com，图片免费可商用。找到喜欢的图片后，右键点击图片，选择"复制图片地址"，粘贴到 path 字段后面即可。

也可以把图片上传到仓库的 assets 文件夹，然后填写路径"/assets/图片文件名"。上传图片前建议先用 https://tinypng.com 压缩，减小文件体积，加快博客加载速度。

### 第四步：如何确认部署成功

每次保存（Commit）后，GitHub 需要约 1～3 分钟重新编译部署博客。正确的检查流程如下：

提交保存后，点击仓库顶部菜单的"Actions"标签，可以看到正在运行的任务。黄色转圈表示正在部署，绿色对勾表示部署成功，红色叉号表示部署失败需要排查。看到绿色对勾后，再去刷新博客页面，就能看到最新效果。

### 第五步：强制刷新浏览器缓存

即使 GitHub 已经部署完成，浏览器可能仍然显示旧版本的缓存页面。解决方法是强制刷新：Windows 系统按"Ctrl + Shift + R"，Mac 系统按"Cmd + Shift + R"，或者用无痕模式打开博客地址。养成"等绿色对勾后强制刷新"的习惯，就不会再觉得更新慢了。

## 五、进阶功能

### 1. 开启评论功能（Giscus）

Giscus 是目前最推荐的博客评论系统，完全免费，基于 GitHub，读者用 GitHub 账号登录即可评论，评论数据存储在你自己的仓库里，永久保留。

**第一步：开启仓库的 Discussions 功能。** 进入仓库 Settings，在 General 页面向下找到 Features 部分，勾选 Discussions，页面自动保存。

**第二步：安装 Giscus 应用。** 访问 https://github.com/apps/giscus，点击 Install，选择"Only select repositories"，选中你的博客仓库，点击 Install 确认安装。

**第三步：获取配置参数。** 访问 https://giscus.app/zh-CN，在仓库输入框填入"用户名/用户名.github.io"，Discussion 分类选择"Announcements"，其他选项保持默认。页面下方会自动生成一段配置代码，记录其中的 data-repo-id 和 data-category-id 两个参数的值。

**第四步：填入 _config.yml。** 打开 _config.yml 文件，找到 comments 部分，将 provider 改为 giscus，然后在 giscus 子项下填入 repo（格式为"用户名/仓库名"）、repo_id、category（填 Announcements）、category_id、mapping（填 pathname）、input_position（填 bottom）、lang（填 zh-CN）、reactions_enabled（填 1）等参数，保存后等待部署完成，打开任意文章拉到底部即可看到评论框。

**评论管理：** 评论存储在仓库的 Discussions 页面，你可以随时进入 Discussions 查看、删除或隐藏评论，也可以锁定某篇文章的评论区。

### 2. 添加背景音乐播放器

为博客添加全站背景音乐，让读者一进入就能听到音乐。

**第一步：准备 MP3 文件。** 推荐从 https://pixabay.com/music 下载免费无版权音乐，下载后将文件重命名为"bgm.mp3"。

**第二步：上传到仓库。** 进入仓库 assets 文件夹，点击"Add file"选择"Upload files"，上传 bgm.mp3，Commit 保存。

**第三步：在 _config.yml 中关闭 HTML 压缩的 endings 选项。** 找到 compress_html 部分，将"endings: all"改为"endings: []"，保存。这一步非常重要，否则播放器代码无法正常注入。

**第四步：创建播放器插件文件。** 在仓库 _plugins 文件夹里新建文件"music_player.rb"，填入播放器代码，设置播放器位置（推荐右下角）、样式（胶囊形半透明）和音乐文件路径，保存后等待部署完成即可。

### 3. 设置时区与社交链接

**设置时区：** 在 _config.yml 中找到"timezone:"字段，填入"Asia/Shanghai"，保存后文章发布时间会显示为正确的中国时间。

**填写社交链接：** 在 _config.yml 的 social 部分，填入 name（你的名字）、email（邮箱，不想公开可留空）、links（社交链接列表，可以填 GitHub 主页、微博等）。底部图标会自动根据链接显示对应的平台图标。

## 六、后续维护

### 1. 日常写作发布流程

养成固定的写作发布流程，可以让你的博客保持持续更新。

推荐流程如下：先在本地用任意文本编辑器写好文章内容（记事本、Word 都可以），按照 Markdown 格式排版好，然后进入 GitHub 仓库的 _posts 文件夹，点击"Add file"创建新文件，按格式填写文件名，粘贴文章内容，Commit 保存，等待 Actions 绿色对勾，强制刷新博客确认发布成功。

### 2. 修改与删除文章

**修改文章：** 进入 _posts 文件夹，找到对应的文章文件，点击铅笔图标编辑，修改内容后 Commit 保存，博客会自动更新。

**删除文章：** 进入 _posts 文件夹，点击要删除的文章文件，点击右上角的"···"三点菜单，选择"Delete file"，Commit 保存即可。文章会从博客中立即消失，但如果开启了评论功能，对应的 Discussion 需要手动到 Discussions 页面删除。

### 3. 管理读者评论

评论统一在仓库的 Discussions 页面管理。点击仓库顶部的"Discussions"标签，每篇文章对应一个 Discussion 帖子。

可以执行的操作包括：删除某条评论（点评论右上角"···"选择 Delete）；隐藏某条评论（点"···"选择 Hide）；锁定某篇文章的评论区（进入对应 Discussion，点右侧 Lock conversation）；删除整篇文章的评论区（直接删除对应的 Discussion）。

GitHub 会在有新评论时发送邮件通知，建议定期查看。

### 4. 图片压缩建议

上传到博客的图片建议先压缩，可以减小仓库体积，同时加快博客加载速度，提升读者体验。

推荐使用免费在线压缩工具 https://tinypng.com，支持 PNG 和 JPG 格式，操作极简单，把图片拖进去自动压缩，下载压缩后的文件即可。一般可以压缩 50%～80% 的体积，画质几乎没有损失。

### 5. 常见问题 FAQ

**问：修改后博客没有更新怎么办？**
答：先去 Actions 页面确认绿色对勾已出现，然后按 Ctrl+Shift+R（Mac 是 Cmd+Shift+R）强制刷新浏览器缓存。

**问：GitHub 访问很慢怎么办？**
答：属于正常现象，可以多刷新几次或换个时间段操作。读者访问博客不需要访问 GitHub，所以不影响博客的访问速度。

**问：文章发布后显示时间不对怎么办？**
答：检查 _config.yml 里的 timezone 字段是否设置为"Asia/Shanghai"，同时确认文章头部信息里的 date 字段末尾加了"+0800"。

**问：以后想再建第二个博客怎么办？**
答：GitHub Pages 主站只能有一个（用户名.github.io），但可以建无限个"项目站"，仓库名随便取，访问地址为"用户名.github.io/仓库名"。

**问：评论框没有出现怎么办？**
答：确认 _config.yml 里 comments 部分的 provider 字段值为"giscus"，以及 repo_id 和 category_id 填写正确。同时确认已在 GitHub 安装了 Giscus 应用，且仓库已开启 Discussions 功能。

**问：仓库容量够用吗？**
答：GitHub 仓库建议不超过 1GB，图片压缩后每张约 200KB，可存 5000 张以上。按每周一篇文章每篇一张封面图计算，约 19 年才能用完，完全不用担心。

**问：可以绑定自己的域名吗？**
答：可以，但需要购买域名（每年约 50～100 元）。购买后在域名服务商处设置 DNS 解析，然后在 GitHub Pages 设置里填入自定义域名即可。免费的".github.io"地址已经足够好用，不是必须绑定自定义域名。
